# /dflow-team 사용 안내

D'Flow 에서 나에게 배정되고 `agent` 태그가 켜진 ready 작업을 찾아, 팀원 N명에게 나눠 동시에 개발시키는 팀장이다.
팀원은 각자 워크트리에서 `/dflow-dev` 를 돌리고, 끝나면 D'Flow 에 완료 보고(승인 대기)를 한다. 팀장은 사람이
승인한 작업을 main 에 머지한다.

## 사용법

```
/dflow-team [인원] <종료시각|종료 요청 전까지> [모델] [WP-XX…]
/dflow-team help
```

인자는 자연어로 써도 된다. 순서도 자유다.

| 인자 | 필수 | 예 | 뜻 |
|---|---|---|---|
| 종료 시각 | 예 | `18:00` · `3일 뒤 06:00까지` · `월요일 09:00` · `종료 요청 전까지` | 새 배정을 멈추는 시각. 빠지면 팀장이 묻는다 |
| 인원 | 아니오 | `2명` · `4명` | 동시에 띄울 팀원 수. 기본 3, 최대 4 |
| 모델 | 아니오 | `opus` · `sonnet` | 팀원이 쓸 모델. 없으면 기본 모델 |
| WP 범위 | 아니오 | `WP-02` · `WP-02 WP-03` · `dict/WP-02` | 새 배정을 그 WP 의 작업으로 좁힌다 |
| 재개 | 아니오 | `--resume 443b8ffe` · `443b8ffe 재개` | 다른 PC 에서 멈춘 작업 등을 손으로 지목해 이어받는다 |

## 예

```
/dflow-team 18:00                       오늘 18시까지, 팀원 3명
/dflow-team 2명 18시까지 opus            오늘 18시까지, 팀원 2명, opus
/dflow-team 18:00 WP-02                 WP-02 작업만 새로 배정
/dflow-team 3일 뒤 06:00까지             사흘 뒤 아침 6시까지 무인으로
/dflow-team 종료 요청 전까지 WP-03        멈추라고 할 때까지 WP-03 만
```

## 종료 시각

- **오늘 시각**(`18:00`): 이미 지난 시각이면 팀장이 다시 묻는다. 밤에 `06:00` 을 쓰면 내일로 추측하지 않고 묻는다.
- **날짜가 붙은 시각**(`내일 07:00`, `3일 뒤 06:00`, `2026-09-21 06:00`): 지금부터 7일 이내만 받는다.
- **종료 요청 전까지**: 멈추라고 할 때까지 돈다. 7일보다 길게 돌릴 때도 이것을 쓴다.
- 시작 보고의 첫 줄에 팀장이 해석한 절대 시각이 나온다. 틀렸으면 바로 "팀장 종료" 로 멈추고 다시 시작한다.

## 멈추기

종료 시각 전이라도 언제든 멈출 수 있다. 진행 중인 팀원의 결과를 잠시(최대 1시간) 기다린 뒤 마감 보고를 한다.

1. 팀장 세션에 말한다: `팀장 종료`, `마감해`, `그만`
2. 다른 터미널에서 종료 파일을 만든다(20초 안에 팀장이 알아챈다).
   ```bash
   touch "$(git -C <팀장 체크아웃> rev-parse --git-path dflow-team.stop)"
   ```

마감 중에 한 번 더 종료를 요청하면 기다리지 않고 곧바로 마감한다. 팀원은 팀장이 끝나도 자기 화면에서 계속 돌며,
다음 팀장이 이어받는다.

## 시작 전 준비

- 팀장 체크아웃은 기본 브랜치(main)이고 깨끗해야 한다.
- `.env` 에 세 가지가 있어야 한다: `DFLOW_API_BASE`, `DFLOW_PATS`,
  `DFLOW_PROJECT_ID`(또는 `DFLOW_PROJECT_MAP`). 프로젝트 바인딩이 없으면 시작하지 않는다. 한 사람이 여러 프로젝트에
  속하면 다른 프로젝트의 작업을 이 리포에서 개발하게 되기 때문이다.
- `DFLOW_PATS` 에 토큰이 둘 이상이면 팀장이 시작할 때 이 리포가 쓸 키를 정해 `.env` 에 `DFLOW_AS=<prefix>` 로 적는다.
  이 리포의 프로젝트에 속한 키가 하나면 묻지 않고 고르고, 둘 이상이면 묻는다. 바꾸려면 그 줄을 고친다. 키 목록은
  `.claude/skills/dflow-work/scripts/dflow.sh profiles` 로 본다. 시작 보고에 `키: <이름> (<email>, <prefix>)` 가 나온다.
- 팀원이 잡을 작업은 D'Flow 에서 `agent` 태그를 켠다. 태그가 없는 작업은 사람 몫이라 건드리지 않는다.
- 팀장은 한 체크아웃에 하나만 뜬다. 다른 계정으로 동시에 돌리려면 클론을 하나 더 만들고 그 `.env` 에 그 계정의
  PAT 를 넣는다.

## 팀원 화면과 질문

- Orca 안에서 띄우면 팀원은 Orca 탭(`dflow-<id8>`)으로 뜬다. 터미널에서 띄우면 tmux 로 뜨며
  `TMUX= tmux -L dflow attach` 로 볼 수 있다.
- 팀원은 **권한 확인 생략 모드**로 돈다. 팀장 세션의 권한 모드와 무관하다.
- 팀원이 결정을 물으면(`blocked`) 팀장이 알린다. 그 탭이나 pane 에서 직접 답하거나, 팀장 세션에 `<id8> <답>` 으로
  답한다.

## 여러 날 무인으로 돌릴 때

- macOS 면 팀장이 절전 방지(`caffeinate`)를 건다. 뚜껑을 닫으면 막지 못하므로 전원을 연결하고 연 채로 둔다.
  Linux 서버는 따로 할 것이 없다.
- 답을 기다리는 팀원은 사람이 답할 때까지 슬롯을 잡는다. 밤사이 슬롯이 줄 수 있다.
- 사용량 한도나 환경 문제로 실패가 2건 이어지면 새 배정을 멈추고 30분마다 1건만 시험한다.

## 그 밖

- 승인은 사람이 D'Flow 웹에서 한다. 팀장은 30분마다(그리고 결과가 올 때마다) 승인된 작업을 main 에 머지한다.
- 반려된 작업은 자동으로 다시 잡지 않는다. `/dflow-dev <id8>` 로 사람이 재작업을 시작한다.
- 마감 보고의 "멈춤" 표에는 자동으로 잇지 못한 작업과 이어받는 명령이 함께 나온다.

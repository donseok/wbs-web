## 원인

### 1. 계약 시험이 "비어 있음" 을 한곳에 목록으로 단정했다

TSK-03-01(dict 공유 계약, 계약 전용 Task)은 다음 두 시험을 만들었다.

- `tests/routes-mount.test.js` #2·#4: 라우트 파일 여덟 개 **전부**에 대해 `createRouter({ db: {} }).stack` 길이가 0 임을 단정한다
  (design.md: "이 Task 가 만든 버전은 경로를 하나도 등록하지 않는다(하류 기능 Task 가 자기 파일에만 추가한다)").
- `tests/domain-contracts.test.js`: `STUBS` 배열에 "아직 `throw new Error('not implemented')` 한 줄뿐이어야 할 함수" 를 모두 나열한다.

두 시험 모두 계약 시점에는 맞다. 하지만 **기능 Task 가 자기 일을 하면 반드시 깨진다.** 기능 Task 는 자기 라우트
파일(`rules.js` 등)만 고치라고 위임받았는데, 시험을 통과하려면 공유 시험 파일의 같은 `expect` 줄과 같은 배열을
고쳐야 한다. 병렬로 돌면 충돌이 확정된다.

TSK-03-01 설계는 이 위험을 **절반만** 봤다. design.md 의 결정(선택지 A/B)은 "병렬 기능 Task 둘이 같은 새 파일을
동시에 만들면 충돌한다" 를 이유로 라우트 파일과 `ROUTES` 배열을 계약 Task 가 미리 만들어 두는 (B) 를 골랐다.
파일 **생성** 충돌은 흡수했지만, 그 파일들을 지키는 **시험**이 새 충돌 지점이 된다는 점은 다루지 않았다.

### 2. 병렬 워커는 서로의 해법을 볼 수 없다

여덟 팀원은 모두 같은 기점 `64412ba` 에서 출발했다. 각 워커는 Design 단계에서 "빈 틀 단정을 어떻게 깰지" 를
스스로 결정했고(TSK-03-12 design.md 「확인 필요 결정」 2번 등), 그 결정은 다른 워커에게 전달되지 않는다. 먼저
머지된 TSK-03-12 의 `IMPLEMENTED` 규약("뒤따르는 Task 는 이 집합에 파일 이름을 더한다")은 main 에 들어간 뒤에
출발한 TSK-03-11 만 따랐다.

### 3. 자동 머지는 충돌을 풀지 않고, 팀장은 공회전한다

- `/dflow-merge` 는 충돌 시 `git merge --abort` 후 "머지 실패(충돌)" 로 보고하고 다음 후보로 넘어간다. 팀장
  스킬은 이것을 "사람이 머지해야 함" 으로 넘긴다. 무인 실행에서는 아무도 풀지 않는다.
- 서버의 선행 판정(`depends_evidence[].reached`)은 선행이 `reported` 면 참이 된다. 선행 코드가 main 에 있는지는
  보지 않는다. 그래서 팀장의 사전 검사(`deps_unmet`)를 통과해 후속 팀원을 띄우고, 워커 행 G 가 main 반영을
  확인해 `skipped` 로 끝낸다. 30분마다(일시 제외 10주기) 같은 일이 되풀이된다.

### 4. `src/server.js` 는 공유 진입점이다

TSK-01-03(인증 가드)과 TSK-03-02(DB 초기화)가 모두 `src/server.js` 의 import 블록에 한 줄씩 더했다. 줄이 맞닿아
있어 git 이 자동으로 합치지 못했다. 규모는 작지만 원인의 성격은 1번과 같다(공유 지점에 각자 추가).

### 5. 계약이 지정한 공용 헬퍼를 계약 Task 가 만들지 않았다 (머지 중 발견)

decisions.md D7·dict-contracts.md §3.1 은 라우트 시험 공용 헬퍼 `tests/helpers/app.js`(`startApiServer`)를 TSK-03-01
산출물로 지정했다. 그런데 TSK-03-01 은 이 파일을 만들지 않았다. 헬퍼가 필요했던 TSK-03-05·TSK-03-08·TSK-01-03 이
**각자 새로 만들었고**, git 입장에서는 같은 경로에 세 파일이 새로 생긴 add/add 충돌이 됐다. 세 판은 반환 형태부터
달랐다(async/동기, `baseUrl` 유무, DB 를 `new Database` 로 열어 FK 가 꺼짐/`createConnection` 으로 열어 FK 켜짐, 빈
응답을 `undefined`/`null`/`''` 로 돌려줌). 호출부도 그 차이에 맞춰 짜여 있어 한쪽 판을 고르면 다른 쪽 시험이 깨졌다.
계약 Task 의 산출물 누락을 기능 Task 가 조용히 메우는 것이 문제다. 누락을 알아챈 워커는 각자 design.md 「확인 필요
결정」 에 적었지만, 서로의 결정은 보지 못했다(2번과 같은 구조).

### 6. 가드 Task 가 먼저 머지된 모든 라우트 시험을 의미상 깨뜨린다 (머지 중 발견)

TSK-01-03 은 `/api` 전체에 역할 헤더(`X-Dict-Role`) 가드를 건다. 텍스트 충돌은 `src/server.js` 한 줄뿐이었지만, 머지하면
먼저 들어온 라우트 시험 6개 파일(85건)이 전부 `401` 로 깨진다. 그 시험들은 전역 `fetch` 로 헤더 없이 요청하기 때문이다.
몇몇 워커는 이를 예상해 "가드가 들어오면 깨진다" 는 주석과 함께 헤더를 미리 싣기도 했지만(tests/routes/units.test.js
는 반대로 "아직 가드가 없어 헤더 없이 부른다" 고 적었다), 규약이 없어 제각각이었다. git 충돌이 아닌 **의미 충돌**이라
`/dflow-merge` 의 충돌 검사로는 잡히지 않고, 머지 뒤 시험을 돌려야만 드러난다. 자동 머지 스윕은 머지 뒤 시험을 돌리지
않으므로, 충돌이 없었다면 이대로 main 에 들어가 이후 모든 워커의 기준선 게이트를 깨뜨렸을 것이다.

## 해소 방법(이번에 쓴 것)

- `tests/routes-mount.test.js`: main 에 먼저 들어온 `IMPLEMENTED` 규약을 따르고, 브랜치의 라우트 파일 이름을 집합에
  더한다. 브랜치가 새로 만든 목록 상수(`REGISTERED_ROUTES` 등)는 걷어낸다.
- `tests/domain-contracts.test.js`: `STUBS` 에서 **양쪽이 구현해서 뺀 함수를 모두 뺀다**. 한쪽 줄을 남기면 이미 구현된
  함수에 "스텁이어야 한다" 를 단정하게 된다.
- `src/server.js`: 양쪽 import·배선을 모두 남긴다.
- `tests/helpers/app.js`: 세 판을 하나로 합친다(async, `createConnection` 으로 FK 켬, `baseUrl` 반환, 비JSON 응답 허용,
  가드 상수로 역할 헤더). 동기로 부르던 호출부(tests/routes/domains.test.js)는 `await` 로 바꾼다.
- 가드 의미 충돌: 역할 헤더를 기본으로 싣는 `tests/helpers/role-fetch.js` 를 두고, 전역 `fetch` 를 쓰던 시험 6개가 그것을
  import 해 전역을 가리게 한다. 호출부는 그대로다.
- 한 건씩 머지하고 전체 시험을 돌린 뒤 push 한다. 결과: 6건 모두 머지, 시험 399건 통과(e2e 는 playwright 미설치로 제외).

## 재발 방지 제안

1. **계약 Task 규칙(`/dflow-wbs`·계약 Task 설계 지침)**: 공유 시험이 "하류 Task 가 채울 것" 을 목록으로 단정하지
   않게 한다.
   - 라우트는 파일마다 자기 시험(`tests/routes-<name>.test.js`)이 등록 여부를 판정하고, 공유 시험은 탑재 순서만 본다.
   - 스텁 판정은 목록 대신 각 함수 시험이 스스로 한다(구현 Task 가 자기 시험 파일만 고친다).
   - 공유 진입점(`server.js`, `routes/index.js`)은 기능 Task 가 고칠 필요가 없게 등록을 자동 수집으로 둔다.
2. **머지 충돌 자동 해소**: 스윕이 충돌을 만나면 팀장이 충돌 해소 전용 팀원을 띄워 main 위로 해소·전체 시험
   통과 뒤 다시 보고하게 한다. 해소 규약(위 「해소 방법」)을 문서로 둔다.
3. **공회전 방지**: 선행이 서버상 `reached` 여도 main 에 없으면(머지 충돌 대기) 팀장 사전 검사에서 걸러 후속을
   띄우지 않는다.
4. **가시화**: 머지 충돌 대기 상태를 좌석표·가상오피스에 표시해 사람이 바로 알게 한다.
5. **선행 규약 공유**: 먼저 머지된 Task 가 공유 파일에 새 규약을 만들면(예 `IMPLEMENTED`), 이미 떠 있는 병렬
   워커에게 알릴 길이 없다. 계약 Task 가 규약을 처음부터 정해 두는 것이 가장 싸다(1번).
6. **계약 산출물 누락 검사**: 계약 Task 의 완료 판정에 "계약 문서가 지정한 파일이 모두 있다" 를 넣는다. 기능 워커가
   계약 산출물 누락을 발견하면 스스로 메우지 말고 `blocked`(또는 계약 Task 재작업 요청)로 올리게 한다(원인 5).
7. **횡단 관심사 Task 의 순서**: 인증 가드처럼 모든 라우트의 동작을 바꾸는 Task 는 기능 Task 보다 먼저 머지되도록
   WBS 선행으로 걸거나, 계약 Task 가 시험 헬퍼에 가드 헤더를 처음부터 넣어 둔다(원인 6).
8. **머지 뒤 시험**: 자동 머지 스윕이 머지 직후 전체 시험을 돌리고, 실패하면 push 하지 않고 되돌린다. 의미 충돌은
   git 충돌 검사로 잡히지 않는다(원인 6).

# WBS 기반 에이전트 코딩 플랫폼 — 설계 킥오프 (PM 브리프)

작성: 2026-08-05 · PM(리더 세션) · 수신: 설계자 A/B/C

---

## 1. 무엇을 만드는가 (사용자 원문 요지)

현 프로젝트(D'Flow / wbs-web)를 **완전 동일하게 복사**한 뒤, 그 위에 **WBS 기반 에이전트 코딩 기능**을 얹는다.

> WBS에 정해진 일정이 되면 개발을 **자동으로 시작**하고, 개발이 끝나면 **테스트 → 검증 → 디버깅 → 배포**까지 진행한 뒤,
> 다음 작업을 **기다리거나 스스로 찾아서 수행**한다.

즉 신규 제품이 아니라 **현 제품의 기능 확장**이다.

## 2. 출발점 — 이미 있는 것 (중복 설계 금지)

**에이전트 작업 루프는 이미 프로덕션에 배포돼 있다.** 2026-07-31 배포, 2026-08-03 재-E2E 완주.
셋 다 설계 시작 전에 아래를 읽을 것. 안 읽고 쓴 설계는 반려한다.

| 자료 | 경로 |
|---|---|
| 설계 정본 | `docs/superpowers/specs/2026-07-31-agent-work-loop-design.md` |
| API 계약 | `docs/design/dflow-agent-work-api-spec.md` |
| 하네스 예제 | `scripts/agent-harness-example.mjs` |
| 서버 라우트 | `src/app/api/v1/agent/work/**` (목록·claim·report·release) |

| 운영 UI | `src/app/(app)/agent-ops/page.tsx` · `src/components/agent/AgentOpsView.tsx` |

현재 동작하는 것: **주문 발행(리프만) → 외부 하네스가 목록 조회 → claim → progress 보고(WBS 실적+부모 롤업) → completion(reported) → 사람이 /agent-ops에서 승인(→100%)**.
안전장치: 미등록 프로젝트 전 라우트 404 · 오시크릿 401 · 완료 100%는 사람 승인 전용(progress는 0~99) · 실패 시 release만(progress 0 보고 금지).

## 3. 빠진 것 — 이번 설계의 진짜 범위

기존 루프는 **"사람이 주문을 발행하고, 외부 하네스가 가져가 구현 보고까지"** 다. 사용자가 원하는 것과의 차이는 넷:

1. **일정 자동 트리거** — 계획 시작일이 되면 사람 개입 없이 주문이 발행되고 착수된다.
2. **개발 이후 파이프라인** — 테스트 → 검증 → 디버깅 → 배포까지 루프가 스스로 진행한다. (지금은 "구현했다고 보고"가 끝)
3. **자율 다음 작업** — 대기하거나 **스스로 다음 할 일을 찾는다**. 무엇을 근거로 고르는가가 설계의 핵심.
4. **스택 이식 + 복제** — MySQL(무료) 기반, 웹서버는 Tomcat 또는 Node 등 대중적인 무상 스택. 현 프로젝트 복사본 위에서.

## 4. 제약 (전원 공통 — 위반 설계는 반려)

- **유료 LLM API를 전제하지 않는다.** 사용자는 유료 Claude/OpenAI API를 쓰지 않는다. 어댑터 뒤에 **동작하는 무료 기본값**이 반드시 있어야 하고, 유료 키는 선택적 업그레이드일 뿐이다. (핵심 제약 — 에이전트 코딩 기능의 실현 가능성이 여기 달렸다)
- **DB는 MySQL 무료판.** 웹서버·런타임은 대중적이고 무상이면 무관(Tomcat/Node 등).
- **원본 리포는 문서 외 무접촉.** 이번 단계는 **설계만**이다. `src/`·`supabase/` 등 코드를 수정하지 않는다.
- **커밋하지 않는다.** 4개 세션이 같은 워크트리를 공유한다. `git add -A` 절대 금지.
- **운영 D-CUBE 데이터 무접촉.** 프로덕션 Supabase를 로컬 dev도 공유한다.
- **위키(wiki) 기능은 작업 금지** — 사용자 지시로 서비스 중단 상태다. 이식 대상에서 제외하고, 언급이 필요하면 "제외" 라고만 쓴다.

## 5. 역할 분담

각자 **자기 파일만** 쓴다. 남의 파일을 열어 읽는 건 자유, 쓰는 건 금지. 겹친다고 판단되면 PM에게 보고하고 멈춘다.

### 설계자 A — 스케줄러 · 작업 도메인 (`01-scheduler-domain.md`)

WBS 일정이 어떻게 "실행"으로 바뀌는가.

- 일정 트리거 모델: 무엇을 기준으로 착수하는가(계획 시작일/선행 완료/의존성), 지연·휴일·타임존, 중복 발행 방지(멱등성)
- 작업 상태 머신: 대기 → 발행 → claim → 개발 → 테스트 → 검증 → 디버깅 → 배포 → 완료/반려. 각 전이의 주체·조건·되돌림
- **자율 다음 작업 선택 정책**: 우선순위 근거(임계경로/지연도/의존성/난이도), 사람 승인이 필요한 경계, 폭주 방지 상한
- 동시성: 여러 에이전트가 동시에 도는 경우 claim 경합·락·스테일 회수
- MySQL 스키마(DDL 초안): 주문·클레임·실행 이력·산출물·승인. 기존 Postgres 스키마와의 매핑
- 기존 `agentWork` 도메인에서 **재사용할 것 / 바꿀 것** 명시

### 설계자 B — 에이전트 실행 엔진 · 품질 게이트 (`02-agent-runtime.md`)

에이전트가 실제로 코드를 쓰고 검증하는 부분.

- 실행 모델: 무엇이 코드를 쓰는가(로컬 CLI 에이전트/무료 호스티드 LLM/규칙 기반), **무료 제약 하에서 실현 가능한 안** 최소 2개 비교 + 권고
- 격리: 워크트리/컨테이너, 동시 실행 충돌, 원본 브랜치 보호
- 프롬프트/작업 계약: WBS 리프 하나가 에이전트에게 어떤 입력으로 전달되는가, 산출물 형식
- **품질 게이트 파이프라인**: 테스트 → 검증 → 디버깅 자동 루프. 실패 시 재시도 횟수·백오프·포기 조건·사람 에스컬레이션
- 배포: 어디까지 자동으로 배포하는가, 롤백 트리거, 승인 게이트 위치
- 실패 규약: 기존 루프의 "실패 시 release만, progress 0 보고 금지" 원칙을 확장 파이프라인에 어떻게 적용할지
- 비용·레이트리밋: 무료 티어 RPM 한계에서 도는 큐 설계

### 설계자 C — 플랫폼 이식 · 인프라 (`03-platform-port.md`)

복사본을 MySQL/무상 스택 위에 올리는 문제.

- **복제 전략**: 무엇을 복사하고 무엇을 버리는가(위키 제외). 리포 분리 방식, 원본과의 향후 동기화 여부
- **Supabase → MySQL 이식 갭 분석(가장 중요)**: 현 제품은 Postgres 위에서 RLS·Supabase Auth·Storage·pgvector에 의존한다. MySQL 무료판에는 이 넷의 대응물이 없거나 약하다. 각각 무엇으로 대체하는가, 대체 비용은 얼마인가, **일부는 이식하지 않는 선택이 옳은지**를 근거와 함께 판정할 것. 이식 불가/고비용 항목은 숨기지 말고 명시한다.
- 런타임: Next.js 유지 vs Tomcat(Java) 전환의 실질 비용 비교 + 권고. 현 코드베이스는 TypeScript/Next.js 15다.
- 인증·권한: 현 3단 권한(슈퍼유저/관리자/멤버)을 새 스택에서 어떻게 재현하는가. RLS 2차 방어선 상실에 대한 대응
- 배포·운영: 호스팅, CI/CD, 마이그레이션 관리, 백업, 관측/로그
- 마이그레이션 경로: 기존 데이터를 옮기는가, 빈 상태로 시작하는가

## 6. 산출물 형식 (공통)

`docs/design/agent-coding-platform/` 아래 **자기 파일 하나**. 한국어. 다음을 반드시 포함:

1. **요약** — 3~5줄. 결론 먼저.
2. **설계 본문** — 위 항목별.
3. **결정이 필요한 사항** — PM/사용자가 답해야 할 질문. 각 질문에 **본인의 권고안과 근거**를 붙일 것. "질문만" 던지지 말 것.
4. **리스크** — 이 설계가 실패한다면 어디서 실패하는가. 낙관 금지.
5. **모르는 것 / 확인 못 한 것** — 추측을 사실처럼 쓰지 말 것. 코드를 확인했으면 `파일:줄`로 근거를 남긴다.

분량보다 **정확성**이다. 확인 안 한 것을 확인한 것처럼 쓰면 그게 가장 큰 실패다.

## 7. PM이 이미 감지한 쟁점 (설계에서 다뤄줄 것)

- **MySQL 전환이 pgvector를 죽인다.** 현 제품의 챗봇·RAG·회의록 검색이 pgvector에 의존한다. → 설계자 C 판정 대상.
- **무료 LLM으로 "코딩 에이전트"가 성립하는가.** 이 기능 전체의 실현 가능성이 여기 걸려 있다. → 설계자 B 판정 대상.
- **"스스로 찾아서 수행"의 안전 경계.** 자율성이 높을수록 폭주 위험이 커진다. 기존 루프가 완료 100%를 사람 승인 전용으로 묶어둔 것과 같은 급의 안전장치가 필요하다. → 설계자 A 판정 대상.

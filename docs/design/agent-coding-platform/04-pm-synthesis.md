작성 2026-08-05 · PM(리더 세션) · 입력: `01-scheduler-domain.md`(A) · `02-agent-runtime.md`(B) · `03-platform-port.md`(C)

## 1. 한 줄 결론

**기능은 성립한다. 그러나 킥오프가 그린 순서(이식 먼저)는 틀렸다.** 세 설계자가 서로 독립적으로, 서로 다른 근거로 같은 지점을 가리켰다 — 이식은 신규 기능보다 크고, 신규 기능은 DB 종류와 무관하다.

## 2. 세 설계자의 핵심 판정

| | 판정 | 근거 |
|---|---|---|
| **A** (스케줄러) | 상태를 늘리지 말고 직교축 `stage`를 추가. 일정 엔진은 **이미 있다**(`task_dependencies` 0029 + `computeDependencySchedule`) | 기존 5상태를 12개로 늘리면 CAS·라우트·테스트가 전부 깨진다 |
| **B** (실행엔진) | **무료 호스티드 LLM으로는 코딩 루프가 성립하지 않는다.** 구독형 CLI 에이전트가 실행자 | 현 LLM 어댑터에 툴 콜 경로가 0줄, 무료 티어 RPM 20 vs 1작업당 수십~수백 턴 |
| **C** (이식) | **MySQL Community는 벡터 검색을 죽인다. MariaDB 11.8 Community면 산다.** Tomcat은 전면 재작성이므로 기각 | 거리함수 `DISTANCE()`가 HeatWave(유상) 전용 · TS 76,425줄·테스트 238파일 |

## 3. 세 설계자가 독립적으로 수렴한 것 (신뢰도 높음)

셋이 서로의 문서를 못 본 상태에서 같은 결론에 도달한 항목 — 이건 우연이 아니다.

1. **자동화의 출구는 사람이 쥔다.** A는 "발행·승인 양쪽을 사람이", B는 "PR까지만 자동, 병합은 사람", C는 "RLS 폐기하되 보상통제 선행". 셋 다 자율성의 상한을 스스로 낮췄다.
2. **실패 채널이 없는 것이 최대 구조 결함.** 현행 계약의 `kind`는 `progress|completion` 뿐이라 **실패를 기록할 곳이 없고**, `release`는 무한 재-claim 루프를 만든다. A(R2)·B(B-2, R2)가 같은 곳을 짚었다.
3. **실적 오염이 가장 비싼 사고.** `progress 0`이 나가면 `actual_pct`를 즉시 덮어쓰고, 그 값은 대시보드·주간보고·PPT로 전파된다. A(R4)·B(R5) 동일.
4. **파일럿 없이 본 구현 금지.** B(R1)는 명시적으로, A(§9-5)와 C(R3)는 "가정값이므로 실측 후 조정" 형태로.

## 4. PM이 즉시 해소한 것

**B의 미확인 1번 — "사용자에게 CLI 구독이 있는가"는 확인됐다.** 이 세션들 자체가 Claude Max 구독으로 도는 Claude Code다(pane 배너 실측). 기존 레퍼런스 하네스도 "로컬 claude CLI 로그인 완료"를 전제로 이미 작성돼 있다(`scripts/agent-harness-example.mjs:7`).

단 경계를 분명히 할 것 — **구독 CLI를 로컬에서 본인 작업에 쓰는 것**과 **제품이 다수 사용자에게 그 구독을 프록시하는 것**은 다르다. 후자는 ToS 위반이고 기존 판단(무료·프로바이더 무관 원칙)이 그대로 유효하다. 따라서 실행자는 **운영자 PC에서 도는 로컬 러너**이지 서버 기능이 아니다. 이 구분이 흐려지면 설계 전체가 무너진다.

## 6. PM 권고 — 경로 β + 파일럿 선행

이유 셋:

1. **에이전트 루프의 핵심은 DB 종류와 무관하다.** CAS claim·404 게이트·시크릿 인증·리프 판정 어디에도 Postgres 고유 기능이 없다(C §5.3 실측). 이식은 이 설계를 바꾸지 않는다.
2. **가장 큰 미지수는 이식이 아니라 실현 가능성이다.** "무료/구독 제약에서 코딩 에이전트가 실제로 완주하는가"는 아직 아무도 모른다. 이걸 모르는 채로 수 주짜리 이식을 먼저 하면, 이식이 끝난 뒤에 기능이 불가 판정을 받을 수 있다.
3. **이식은 "동작하는 명세"가 있을 때 더 싸다.** 기능이 원본에서 돌고 있으면 이식은 재현 작업이 되고, 인수 조건이 명확해진다.

**따라서 다음 단계는 설계 확장이 아니라 파일럿 1건이다** — 실제 WBS 리프 하나를 골라 기존 루프 + 품질 게이트로 완주시키고, 완주율·시도 횟수·소요시간을 실측한다. A의 lease 30분·재시도 2회, B의 build 10분·test 15분은 **전부 근거 없는 가정값**이며 이 파일럿이 그것을 실측값으로 바꾼다.

## 8. 설계 간 미해소 충돌 1건

`agent_projects`에 자동화 설정 컬럼을 붙일지(A), `project_settings` 설정 계층으로 통합할지(C)가 충돌한다. A가 "C의 방침을 따르겠다"고 양보를 선언했으므로 **C 방침 채택**으로 PM이 종결한다. 다만 게이트 판정과 상한 판정이 한 행에서 끝나던 A의 이점은 잃으므로, 구현 시 조인 1회를 감수한다.

## 9. 이 문서가 확인하지 않은 것

- 세 문서의 코드 인용(`파일:줄`)을 PM이 전수 재검증하지는 않았다. 표본으로 A의 상태 상수·B의 `kind` 열거·C의 런타임 판정만 교차 확인했다.
- 이식 기간 견적은 셋 다 숫자를 내지 않았고, PM도 내지 않는다. 근거가 없다.

# PM 브리프 2 — 맥미니 자체 호스팅 + Tomcat 전환 재검증

작성 2026-08-05 · PM · 수신: 설계자 A/B/C
선행: `04-pm-synthesis.md`(결정 P1~P5) · `13-baseline-measurements.md`(실측)

## 1. 사용자가 새로 제시한 조건 (원문 요지)

1. **맥미니를 서버로 만든다.** M4 칩, "256GB 메모리, 256GB 스토리지"라고 진술.
2. 그 위에 **MariaDB + Tomcat**을 설치해 서비스한다.
3. **사용자가 서버에 접속 → WBS 확인 → 작업을 자동으로 부여받고 → 결과값을 돌려주는** 구조.
4. 전체를 다시 검증할 것.

## 2. 이 조건이 기존 결정 셋을 흔든다

| 기존 결정 | 새 조건과의 관계 |
|---|---|
| **P3 = Tomcat 기각, Node 유지** | **정면으로 뒤집힌다.** 사용자가 Tomcat을 명시했다. 불과 몇 분 전 "예시였다 — Node 유지"를 택했으므로, 비용을 정확히 다시 제시한 뒤 사용자가 재확정해야 한다 |
| **P4 = 사내 서버 없음/미확인** | **해소.** 맥미니가 그 서버다. 다만 "무상"의 의미가 바뀐다 — 하드웨어 비용은 이미 지출됐고, 새로 생기는 것은 전력·네트워크·운영 부담이다 |
| **P1 = 경로 β (기능 먼저, 이식은 뒤)** | **재검토 필요.** MariaDB+Tomcat 자체 호스팅을 지금 하겠다는 것은 사실상 α(이식 먼저)로의 회귀다. β를 유지하면서 자체 호스팅만 먼저 할 수도 있다(Node+MariaDB) — 이 분기를 명확히 할 것 |

## 3. PM이 실측한 것 / 실측하지 못한 것

**실측(2026-08-05, 현 세션이 도는 기계):**

- 개발 기계는 맥미니가 아니라 **MacBook Air M3 · 8GB RAM · 228GB 디스크 중 여유 26GB(88% 사용)** 다.
- 즉 **현 개발 환경에서 로컬 LLM·컨테이너·다중 워크트리를 돌릴 여유가 거의 없다.** 러너를 맥미니로 옮기는 선택이 이 제약을 푼다.

**실측 불가 — 사용자 확인 대기:**

- **맥미니의 실제 RAM.** 진술된 "256GB 메모리"는 맥미니에 존재하지 않는 구성이다(M4 16/24/32GB, M4 Pro 24/48/64GB). 256GB급 통합메모리는 Mac Studio M3 Ultra(최대 512GB) 계열이다. **스토리지 256GB와 혼동했을 가능성이 높다.**
  → **설계자 B는 이 숫자를 사실로 쓰지 말 것.** RAM 시나리오를 **16GB / 32GB / 64GB / 256GB(Studio급)** 로 나눠 각각 무엇이 가능한지 표로 낼 것.
- **스토리지 256GB의 여유분.** macOS + 개발도구가 이미 상당량을 먹는다. MariaDB + Tomcat + 워크트리 + 빌드 캐시 + (로컬 모델을 쓴다면) 수십 GB 모델 파일이 여기 다 들어가야 한다. **256GB는 이 용도로 빠듯하다** — 2026-08-05 Supabase 장애의 원인이 디스크 풀이었다는 점을 상기할 것.

## 4. 새 조건이 만드는 미해결 질문

### Q-A. "사용자가 작업을 자동으로 부여받고 결과값을 돌려준다"의 주체가 누구인가

두 해석이 완전히 다른 시스템을 만든다.

- **해석 1 — 사람:** 팀원이 웹에 접속해 자기에게 자동 배정된 WBS 작업을 받고, 완료 후 결과를 입력한다. 이건 **작업 배정·수행 관리 시스템**이고, 에이전트 코딩과 무관하다.
- **해석 2 — 에이전트 러너:** 각 개발자 PC의 러너가 서버에 붙어 작업을 claim하고 코드를 만들어 결과를 반환한다. 이건 **기존 에이전트 루프의 다중 클라이언트 확장**이다.
- **해석 3 — 둘 다:** 사람과 러너가 같은 큐를 공유한다.

**PM은 해석 3을 유력하게 보지만 확정하지 않았다.** 설계자 A는 세 해석을 각각 설계 관점에서 분해하고, 해석이 갈리는 지점에서 무엇이 달라지는지 표로 낼 것.

### Q-B. 외부 노출의 실체

"사용자가 이 서버에 접속"은 집/사무실의 맥미니를 인터넷에 노출한다는 뜻이다. 다음이 전부 새로 생기는 일이다 — 고정 IP 또는 DDNS, 포트 포워딩 또는 터널(Cloudflare Tunnel/Tailscale), TLS 인증서와 갱신, 인증·세션, 백업, 정전·재부팅 복구, 그리고 **가정용 회선의 상향 대역과 ISP 약관**.

지금까지 Vercel+Supabase가 공짜로 해주던 것이 전부 운영자 일이 된다. 설계자 C가 이것을 **실행 가능한 설치·운영 절차서** 수준으로 내려야 한다. 추상적 권고가 아니라 명령과 순서로.

### Q-C. Tomcat 전환의 실비용

`03-platform-port.md` §4는 TS 76,425줄·461파일·테스트 238파일을 근거로 Tomcat을 기각했다. 사용자가 다시 요구했으므로 **감정이 아니라 숫자로 다시** 제시해야 한다. 설계자 B가 담당한다.

**중요:** "안 된다"고 쓰지 말 것. **"이 비용을 내면 된다"** 로 쓸 것. 결정은 사용자가 한다.

## 6. 전원 공통 규칙

- **숫자를 지어내지 말 것.** "256GB 메모리"는 미확인이며 사실로 쓰지 않는다. 못 잰 것은 못 쟀다고 쓴다.
- **기각하지 말고 가격표를 붙일 것.** 사용자가 요구한 것(Tomcat·자체 호스팅)을 "안 된다"로 닫지 말고, 비용·리스크·대안을 제시해 사용자가 결정하게 한다.
- 기존 문서(`01`~`13`)와 충돌하는 결론이 나오면 **어느 문서의 어느 항목이 무효가 되는지 명시**할 것.

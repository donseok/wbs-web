## 0. 한 장 요약 — 이것만은 꼭

1. **D'Flow 는 구현이 끝났고, `MINUTES_FOLDER_PATH_ENABLED=false` 로 배포한다.**
   R1 구간에서 `POST /minutes` 는 `folder_path` 를 **키 부재와 동일하게 무시**한다 — 편철도 검증도 없다.
   즉 **또박또박 1차(`ddobak-W1`)는 언제 배포해도 무해하다.**
2. **3차(재편철)를 2차(전송 전환)보다 먼저 돌린다.** 순서가 뒤집히면 사람이 정리해 둔 편철이 되감긴다.
3. **배치는 `pmo_admin` 계정만 쓸 수 있다.** `ACTOR_EMAIL` 이 `donseok75@gmail.com` 이 아니면 전건 403.

## 1. 계약 v2.4 신설·변경 (§2-E 9건)

| # | 항목 | 또박또박 영향 |
|---|---|---|

| 2 | §4c.2 `from: string[] \| null` 명시 | **`Array` 로 타입 고정하면 깨진다**(`null` = 이동 전 미분류) — `ddobak-W9` |
| 3 | §4.3·§4c.2 **`folder_path_status`** 신설 | `exact`·`truncated`·`partial`·`unclassified`. **절단·부분편철·미분류가 사용자에게 보이는 유일한 경로** — `ddobak-W8` 배지 |

| 7 | 배치 `pmo_admin` 게이트 + `403 forbidden_role` | 위 0-3 |

| 9 | 비활성 팀 재전송 **500 → 400 + 명시 사유** | D'Flow 에서 팀을 비활성화하면 그 팀 회의록의 **재전송이 실패**한다. 이제 원인이 응답에 실린다 |

### ⚠️ 계약 §4.8 표의 예외 1건 (2026-07-28 추가)

계약과 결정문 모두 "R1 은 `POST /minutes` 동작을 1비트도 바꾸지 않는다"고 적었는데 **예외가 하나 있다.**

**`folder_path` 키가 없는 재전송에서 `team` 만 바뀌면, R1 에서도 폴더가 새 팀 루트로 이동한다**(§4.5-11).
`folder_path` 편철과 무관한 별개 규칙이라 플래그 게이트 밖이다 — 담당을 정정한 재전송이
"team 은 ERP 인데 폴더는 MES 서브트리"인 데이터를 남기지 않게 하려는 것이다.

→ R1 구간을 "무동작"으로 가정하고 검증 계획을 세우면 이 한 건에서 어긋난다.
새 팀 루트가 없으면 폴더를 **유지**하고 등록은 성공한다.

## 2. 차수·순서 제약 (지켜야 할 것 3개)

```
[D'Flow] R1  플래그 false 로 배포 — POST /minutes 동작 불변, 배치·archived 만 열림
   ── 0차  ddobak-W18  계약 사본 v2.1 → v2.4 동기화
   ── 1차  ddobak-W1·W9·W10·W11·W14·W17   ← 언제 내도 무해
   ── 3차  ddobak-W12·W13  재편철 1회차 **dry-run**
   ── 양측  대조표 정리 (사람 판단 구간)
   ── 3차  재편철 1회차 APPLY
[D'Flow] R2  플래그 true 전환
   ── 2차  ddobak-W2~W8·W19   ← 반드시 R2 이후
   ── 3차  재편철 2회차 (창 구간 전송분만)
[D'Flow] R3  연결 초기화 개방      ← ddobak-W14 배포 확인 후
   ── 4차  ddobak-W15·W16 자동 링크
[D'Flow] R4  폴더 D&D 개방        ← 재편철 1회차 APPLY 후
```

1. **`dflow-W24` ≤ `ddobak-W14` ≤ `dflow-W10`** — 앞서면 archived 를 "연결 해제"로 오진하고,
   뒤서면 **중복 회의록 + 원본 고아**가 생긴다(자가 치유 안 됨). `W24` 는 R1 에 포함되므로 실질 제약은 "R1 이후, R3 이전".
2. **또박또박 2차는 R2 이후.** 뒤집히면 그 구간 전송분이 "접두도 없고 폴더도 안 잡힌" 상태가 된다.
3. **재편철 1회차는 R2 이전.**

## 3. 반드시 반영해야 할 호출부 수정 3건 (`include_archived`)

D'Flow 가 `include_archived` + 응답 `archived: boolean` 을 열었지만(`W24`),
**또박또박 호출부가 안 바뀌면 죽은 기능**이고 보관분 오진이 그대로 남는다.

| # | 조치 | 없으면 |
|---|---|---|
| ① | `dflow/status` 의 존재 확인(`list_minutes(external_id:)`) 호출에 `include_archived=true` | `exists_on_dflow: false` 오진이 그대로 |
| ② | 자동 링크의 `GET /minutes?linked=true` **페이지 순회에도** `include_archived=true` + `archived: true` 행은 "존재함(보관)"으로 차집합에서 제외 | 기본값에서는 보관분이 목록에 아예 없어 **제외할 대상으로 인식조차 안 된다** |
| ③ | `ddobak-W14` 문구를 **초기화 / 보관 / 삭제** 3갈래로 세분화 + "D'Flow 에서 보관 해제" 안내 추가 | 사용자가 안내받은 두 갈래가 **둘 다 실패**한다(찾기=목록에 없음, 새로 전송=409 archived) |

⚠️ **`linked=false`(연결 후보 조회)에는 켜지 말 것** — 보관분은 claim 대상이 아니다(`POST /minutes/link` 가 409).
라우트는 이 조합을 막지 않으므로 **호출 측 규약**으로 지킨다.

## 4. 나머지 통보

| # | 내용 |
|---|---|
| 5 | 배치 `status` 사유 2개 추가 — `folder_error`·`update_failed` 는 **DB 실패 계열이라 재실행으로 해소**된다. 기존 4개는 입력·전제 문제라 재실행해도 같다 |
| 6 | **dry run 은 폴더를 만들지 않는다** → 목표 폴더가 없으면 `moved` + `folder_id: null` |
| 7 | 깊이 5 초과는 **절단**한다(400 아님). 또박또박 쪽 사전 경고를 권한다 — 계산식 `folder_path.length + (루트가 팀코드면 0, 아니면 1)`, **경고는 `teamOverride` 확정 후 재평가**. ⚠️ "루트가 팀코드인가" 판정에 **팀 목록을 하드코딩하지 말 것**(런타임 마스터라 6번째 팀이 등록되면 어긋난다) — `GET /minutes/meta` 의 `teams` 를 쓸 것 |
| 8 | 폴더명 **60자 초과는 400 거절**(절단하지 않는다). 검증은 **NFC 정규화 이후** 길이 기준이다 |
| 9 | **R4(폴더 D&D)는 재편철 1회차 APPLY 후에 열린다** — D'Flow 가 서버 플래그로 닫아 뒀다. 그 전에 D'Flow 화면에서 회의록을 옮기면 그 건이 재편철에서 `manual_placement` 로 skip 된다 |
| 10 | **T4「오매칭 후 본문 복구」가 또박또박 4차 착수 조건이다.** D'Flow 백로그에 등재했고(`docs/design/folder-path-backlog.md`), 닫히기 전까지 자동 링크 v1 은 **자동 claim 없이 dry-run 리포트 + 사람 승인**만 허용한다 |

## 6. 대조 기준표

재편철 1회차 대상은 **20건**이다(2026-07-28 재실측 — 결정문 작성 시점의 19건에서 1건 늘었다).
현재 위치 전체는 결정 정본 `dflow-decisions-final-2026-07-27.md` **§8 부록** 표를 볼 것.

- 팀 루트 잔류 **3건**(ERP·MES·PMO 각 1) — 무조건 이동 대상
- 하위 폴더 편철분 **17건** — 조상 규칙으로 자동 판정, 남는 것만 사람 판정
- 미분류 **0건**

⚠️ 이 숫자는 계속 움직인다(사용자가 D'Flow 에서 폴더를 정리 중이다).
**대조표를 요청하기 직전에 D'Flow 가 한 번 더 재실측해 보낸다.**

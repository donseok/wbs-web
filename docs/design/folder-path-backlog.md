# folder_path 연동 — 별건 티켓 원장 (2026-07-28)

> 결정 정본 `dflow-decisions-final-2026-07-27.md` **§2-H-4 · §6** 이 "**별건 티켓으로 등록한다**"로
> 확정했으나 등록처가 정해지지 않아 어디에도 등재되지 않았다. 감사에서 확인한 사실:
>
> - GitHub Issues: `donseok/wbs-web` 는 `has_issues: true` 인데 **이슈 0건**(전 리포 0건)
> - 앱 내 이슈관리(`/issues`, `issues` 테이블): 총 **1행**, 무관한 ERP 업무 이슈
> - 리포 안 백로그 문서: 없었음
>
> **이 문서가 그 임시 원장이다.** 트래커가 정해지면 4건을 옮기고 여기에는 티켓 번호만 남긴다.
>
> ⚠️ **원장이 곧 트래커는 아니다.** 문서는 알림도 담당자도 마감도 없다 — 아래 「등록처 결정」을
> 닫기 전까지는 "적어두었다"일 뿐 "관리되고 있다"가 아니다.

## 등록처 결정 — 미결 (사람 판단)

| 안 | 장점 | 단점 |
|---|---|---|
| **(a) GitHub Issues** | 개발 백로그의 표준 자리. 커밋·PR 연결됨 | `gh auth login` 필요(현재 미인증). 리포가 public 이라 내용 노출 |
| (b) 앱 내 `/issues` | 이미 운영 중이고 PMO 가 본다 | **업무 이슈용**이다. 개발 부채가 섞이면 프로젝트 이슈 통계가 오염된다. 프로젝트 귀속이 강제라 "프로젝트 없는 기술부채"를 담을 자리가 없다 |
| (c) 이 문서 유지 | 비용 0 | 알림·담당·마감 없음. 잊힌다 |

→ **권고는 (a)**. (b)는 운영 데이터에 개발 부채를 섞는 것이라 반대한다.

## T1 — 폴더 권한을 `created_by` 에서 분리

**근거**: 결정 §2-H (권고안 C-1 이 "진짜 해법"으로 지목) · §6

지금 D'Flow 는 폴더 개명·삭제 권한을 `minute_folders.created_by` 로 판정한다. 그래서:

- 배치 재편철이 만든 폴더는 전부 `ACTOR_EMAIL`(`donseok75@gmail.com`) 소유가 된다
- 그 폴더를 손댈 수 있는 사람은 그 한 명과 `pmo_admin` 뿐이다
- 재편철은 한 번이지만 **그 폴더들은 계속 남는다**

실측상 41명 중 28명이 `pmo_admin` 이라 영향 인구는 13명이고 요청 경로도 있어 **심각도는 낮췄지만**,
소유권이 사람에게 붙어 있다는 구조 자체는 그대로다. 팀 폴더는 **팀 것**이어야 한다.

**해야 할 것**: 폴더 권한을 `created_by` 대신 팀 귀속(루트 팀코드 파생) + 역할로 판정하도록 전환.
스키마 변경이 필요할 수 있다(`minute_folders.team_code` 또는 권한 테이블).

**차단 관계**: 없음. 언제든 착수 가능.

## T2 — 깊이 정책 3중 분기 통일

**근거**: 결정 §6 · 작업지시 §12

같은 앱 안에서 폴더 깊이 상한(5단) 초과를 세 곳이 **다르게** 처리한다:

| 경로 | 동작 | 위치 |
|---|---|---|
| UI | 버튼을 아예 숨긴다 | `MinutesExplorer` — `folderDepthOf` 로 판정 |
| 서버 액션 | 거절한다 | `createMinuteFolder` / `moveMinuteFolder` |
| 외부 API | **절단**한다(5단째에 편철) | `resolveFolderPath` — `folder_path_status: "truncated"` |

외부 API 의 절단은 결정 §2-C 로 **정본 확정**됐다(400 거절로 바꾸지 않는다). 문제는 나머지 둘과
어긋난다는 것이고, 사용자가 "왜 여기선 되고 저기선 안 되나"를 겪는다.

⚠️ **`W21`(폴더 D&D)이 열릴 때 다시 터진다** — 드롭으로 깊이를 넘기는 조합이 생긴다.
현재 D&D 는 `MINUTES_FOLDER_DND_ENABLED=false` 로 닫혀 있으므로 **R4 개방 전에 이 티켓을 닫는 것이 좋다.**

**차단 관계**: R4(D&D 개방)와 맞물린다.

## T3 — zip 그룹핑 축을 제목 → 폴더로

**근거**: 결정 §6

회의록 zip 내려받기의 그룹핑이 **제목의 하이픈 접두**(`물류-…`, `기타-…`)를 축으로 삼는다.
또박또박 2차에서 접두가 제거되면 그룹핑이 무너진다(데이터 손실은 없고 묶음만 흐트러진다).

⚠️ **해결책을 "제목에서 하이픈을 뗀다"로 가면 안 된다** — 정상적으로 하이픈이 들어간 제목까지
훼손한다. 결정이 명시적으로 금지한 방향이다.

**해야 할 것**: §6 폴더 중심 재편이 자리 잡은 뒤 그룹핑 축을 **폴더**로 교체.

**차단 관계**: 또박또박 2차(접두 제거) 이후 표면화. R4 이후 착수가 자연스럽다.

## T4 — 오매칭 후 본문 복구 ⚠️ **또박또박 4차 착수 게이트**

**근거**: 결정 §6 — "별건이되 **4차 착수 조건에 건다**"

자동 링크(또박또박 4차)가 회의록을 잘못 claim 하면 본문이 덮인다. 지금 **되돌릴 수단이 없다** —
버전 패널에 되돌리기 액션이 없다.

그래서 결정은 자동 링크 v1 에서 **자동 claim 을 끄고 dry-run 리포트 + 사람 승인만** 허용하기로 했다
(미연결 21건 규모라 비용이 거의 없다).

**해야 할 것**: 버전 패널에 "이 버전으로 되돌리기" 액션 추가. `minute_versions` 는 append-only 라
데이터는 이미 있다 — UI 와 서버 액션만 붙이면 된다.

⚠️ **이 티켓은 단순 백로그가 아니라 또박또박 4차의 착수 조건이다.** 방치하면 4차가 막힌다.
**등록 후 그 사실을 또박또박에도 통보해야 한다** — 현재 통보 목록 11건에 이 항목이 빠져 있다.

**차단 관계**: 또박또박 4차(`ddobak-W15`·`W16`)를 막고 있다.

## 부록 — 이 문서에 담지 않은 것

아래는 **별건이 아니라 조건부 대기**다. 여기 적으면 "언젠가 할 일"로 강등돼 잊힌다.

| 항목 | 상태 | 여는 조건 |
|---|---|---|
| R3 — `clearMinuteExternalId` 를 §9.4-2 원안으로 복귀 | 코드에 한시 게이트 유지 중 | `ddobak-W14` 프로덕션 배포 확인 |
| §2-B 예비안 — `external_id` 정확 조회 archived 면제 | **의도적 미구현** | 또박또박이 호출부 3곳 수정 불가로 회신할 때만 |
| 깊이 5 초과를 400 거절로 전환 | 절단 유지가 정본 | 또박또박의 깊이 분포 집계가 0에 가까울 때 재검토 |
| 마이그레이션 테스트를 실행 기반으로 | 현재 SQL 텍스트 검사뿐 | 전용 테스트 Postgres 확보 |

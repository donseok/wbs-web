## 2. D'Flow 남은 작업 (우선순위 순)

### 2-1. 런타임 스모크 — **머지 전 필수**

단위·통합 테스트로만 덮여 있고 **실호출 검증이 0이다.** 계약 §14.2 curl 스모크 + §14.3 E2E(E6~E17).
최소한 이 5개:

| # | 확인 | 기대 |
|---|---|---|
| 1 | 플래그 `false`에서 `folder_path` 실어 전송 | 201, 팀 루트 편철, 응답 `folder_path=[팀코드]` — **오늘과 동일** |
| 2 | 배치 프로브 `items: []` + `dry_run` | 200 + 전 카운트 0 |
| 3 | 배치 프로브를 **비관리자 계정**으로 | 403 `forbidden_role` |
| 4 | 플래그 `true` 전환 후 3단 경로 전송 | 탐색기에 같은 경로 생성·편철, `folder_path_status: "exact"` |
| 5 | `GET ?external_id=…&include_archived=true` (보관분) | 1건 + `archived: true` |

⚠️ **전용 테스트 프로젝트 또는 스테이징에서.** 운영 데이터에 쓰기 금지.

### 2-2. R1 / R4 분리 — ✅ **해결됨 (2026-07-28, (c) 채택)**

지금 브랜치엔 R1(API)과 R4(UI D&D)가 **같이** 있지만, D&D 를 `MINUTES_FOLDER_DND_ENABLED`(기본 `false`)
뒤에 두어 **함께 머지해도 안전**하다. 재편철 1회차 APPLY 후 env 만 켜면 개방된다(코드 배포 불필요).
상세 = 진행 원장 §9. 범위는 **드래그앤드롭 한정** — [이동] 버튼·폴더 트리 선택·폴더 CRUD 는 그대로 열려 있다.

### 2-3. 배포 (R1)

1. `main` 머지
2. Vercel env에 **`MINUTES_FOLDER_PATH_ENABLED=false`** 설정 (없으면 기본 false지만 명시 권장)
3. 배포 후 §2-1 스모크 1·2·3 재확인
4. 또박또박에 §4 통보

### 2-4. 재편철 1회차 (결정 §4) — 사람이 판단하는 유일한 구간

| 단계 | 주체 |
|---|---|
| ① 19건 전량 `dry_run: true`, `overwrite_manual: false` (1요청) | 또박또박 |
| ② `from`/`to`/`status` 대조표 회신 | 또박또박 |
| ③ `manual_placement` 잔여 건마다 어느 쪽이 정답인지 판정 | **PMO** |
| ④ D'Flow 위치가 정답인 건 → 또박또박에서 폴더를 그쪽에 맞춰 이동 | 또박또박 |
| ⑤ 또박또박 위치가 정답인 건만 `items`에 담아 APPLY | 또박또박 |

⚠️ **1회차 dry-run의 `manual_placement` 건수를 장애로 읽지 말 것.** 조상 규칙 적용 후에도 몇 건은
정상적으로 남는다(사람이 다른 가지로 옮긴 건). **`OVERWRITE_MANUAL`을 켜는 근거가 아니다** — 켜면
사람이 정리한 17건을 덮는다.

### 2-5. R2 전환 (플래그 `true`)

조건 3개가 **모두** 충족된 뒤: ① 재편철 APPLY 완료 ② 19건 대조 정리 완료 ③ 또박또박 2차 준비 통보.
코드 배포 없이 env 전환 + 재배포. **또박또박 2차(제목 접두 제거)는 반드시 이 뒤.**

### 2-6. R3 — 연결 초기화 개방

현재 `clearMinuteExternalId`가 **`pmo_admin` 한시 게이트**다(결정 §3 R3).
`ddobak-W14` 배포가 확인되면 §9.4-2 원안(`checkOwner` = 작성자 또는 `pmo_admin`)으로 되돌릴 것.
**되돌릴 지점은 코드 주석에 명시해 뒀다** (`src/app/actions/minutes.ts`의 `clearMinuteExternalId`).

### 2-7. R4 — 폴더 중심 UI(D&D) 개방

재편철 1회차 APPLY 완료 후 Vercel env 에 **`MINUTES_FOLDER_DND_ENABLED=true`** 를 넣고 재배포.
코드 변경은 없다. 되돌리려면 값을 지우거나 `false` 로 두면 즉시 닫힌다.

### 2-8. 별건 티켓 (결정 §6)

- **폴더 권한을 `created_by`에서 분리** — 결정 §2-H가 "진짜 해법"으로 지목, 등록하기로 확정
- **깊이 정책 3중 분기 통일** — UI=버튼 숨김 / 서버 액션=거절 / 외부 API=절단. `W21` 들어오면 재발
- **zip 그룹핑 축을 제목 → 폴더로** — 접두 제거의 부수영향. 제목에서 하이픈 떼는 방향은 금지
- **오매칭 후 본문 복구** — 버전 패널에 되돌리기 액션 없음. 4차(자동 링크) 착수 조건

## 3. 판단 필요 2건 (내가 임의로 진행하지 않은 것)

### 3-1. R1 / R4 분리 방식 — ✅ **결정됨 (2026-07-28): (c) UI에도 플래그**

| 안 | 내용 | 비용 |
|---|---|---|
| (a) 브랜치 분리 | UI 커밋을 떼어 별도 브랜치로 | 커밋이 서버/UI를 오가며 얽혀 있어 **체리픽 수술 필요**, 실수 여지 |
| (b) 함께 배포 + 운영 공지 | 재편철 끝날 때까지 D&D 자제 공지 | 코드 0, 사람 규율 의존 |
| **(c) UI에도 플래그** ← **채택** | `W25`와 같은 패턴으로 D&D를 env 뒤에 | 코드 소량 |

구현 완료 — `MINUTES_FOLDER_DND_ENABLED`. UI(draggable·드롭)와 서버 액션(`moveMinuteFolder`) 양쪽에
걸었고, 서버 게이트가 인증보다 앞이라 UI 를 우회해도 통하지 않는다. 테스트 6건.

### 3-2. Q2 — §6.8 수용기준 문구

「회의록 D&D 다른 팀으로 이동 → `team_code` 갱신 **&&** 위키 철회·재빌드 발생」은 **현재 스키마로
달성 불가**다. `wiki_rebuild_required := old_project_id 변경 or 시간축 변경` 이고 `team_code`가 없다(운영 DB 실측).
`team_code`는 `v_index_content_changed`에만 들어가 **검색 인덱스(ai_documents) 재적재**만 일으킨다.

구현은 RPC 경유로 했다(raw update보다 명백히 옳다 — raw면 ai_documents가 옛 팀으로 남는다).

✅ **결정됨 (2026-07-28): 수용기준을 「검색 인덱스(`ai_documents`) 재적재 발생」으로 정정.**
팀이 바뀌어도 본문·프로젝트가 그대로면 위키 근거는 변하지 않으므로 재빌드가 옳은 동작도 아니다.
작업지시 §6.8 에 정정 근거를 함께 남겼다. 코드 변경 0.

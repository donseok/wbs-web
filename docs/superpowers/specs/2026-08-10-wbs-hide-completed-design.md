# WBS 완료 숨기기 — 설계

날짜: 2026-08-10
상태: 승인됨 (사용자 승인 — 부분완료 구간 흐림 유지 · 시트+간트 공통 · 계정 전역 저장)

## 배경과 목표

프로젝트가 진행될수록 WBS 시트에 완료 행이 쌓여 "남은 일"이 눈에 들어오지 않는다.
완료된 작업을 숨겨 확인을 쉽게 하되, **부분완료 구간(예: 자식 5개 중 4개 완료)이
잘못 사라지거나 "다 끝난 것처럼" 오해되는 화면을 만들지 않는 것**이 핵심 요구다.

구조적으로 이 걱정은 대체로 해소되어 있다: 부모의 status 는 저장값이 아니라
자식 가중 롤업으로 재판정한 파생값(`rollup.ts` computeNode)이라, 4/5 완료 부모는
대체로 done 이 아니다. **단 두 엣지에서 부모 status 가 done 이 될 수 있다** —
(1) round1 반올림: 리프 원시 99.8 + 완료 형제 4개 → 롤업 (400+99.8)/5 = 99.96 →
round1 = 100.0 → statusOf done (`rollup.ts:41-43`, 검증 시 수치 확인),
(2) 가중치 0 미완 자식은 가중평균에서 소거. 그래서 숨김 판정은 부모 status 가 아니라
**리프 원시값 검사**로 한다(아래 판정 규칙 — 두 엣지 모두에 안전). 남는 설계 문제는
"완료된 자식 4건을 어떻게 보여줄 것인가"이며, 사용자는 **흐림 유지** 방식을 선택했다.

## 결정 사항

| 결정 | 내용 | 근거 |
|---|---|---|
| 표현 방식 | 부분완료 구간의 완료 행은 숨기지 않고 **흐림(dim)** 표시. **전부 완료된 구간(자식을 가진 노드)만 서브트리 통째 숨김** | 사용자 선택 (대안: 'N건 숨김' 배지, 표식 없는 단순 숨김 — 기각) |
| 적용 범위 | 시트+간트 공통 — 두 뷰는 같은 컴포넌트의 같은 `flatRows` 를 공유하므로 토글 하나로 항상 일치 | 사용자 선택 |
| 상태 저장 | `UiPrefs.wbsHideDone`(계정 전역, 프로젝트 무관). JSONB 병합이라 DB 마이그레이션 불필요 | 사용자 선택 |
| 기본값 | 꺼짐 | 기존 화면 동작 무변경 원칙 |
| 완료 판정 | 리프의 **원시 actualPct ≥ 100** (`statusOf` 의 done 계약, 반올림 금지) | `progress.ts:33` 주석이 명시한 계약 — 99.5% 오숨김 차단 |
| 검색 상호작용 | **검색이 우선** — 검색어가 있으면 숨김 필터 미적용(완료 작업도 검색으로 찾을 수 있어야 함). 흐림은 유지 | 검색은 이미 접힘도 전체 무시하는 선례(`flatRows` 의 matchKeep 분기) |
| 롤업·집계 | `computeTree`/rollup/overallProgress 무접촉 — 필터는 표시 계층 한 곳 | 대시보드·보고서 단일 출처 보호 |

## 판정 규칙 (순수 함수)

- **subtreeAllDone(n)**: n 이하 **모든 리프**의 원시 `actualPct ≥ 100`.
  - 리프 판정은 `children.length === 0` (`tree.ts` collectLeaves 와 동일한 도메인 규약).
  - `actualPct` 는 `number | null` — null 은 미완으로 취급(`?? 0`, `project-status.ts:46` 규약).
    리프의 `rolledActualPct` 는 원시값과 동일하므로(`rollup.ts:38`) 어느 쪽을 써도 등가.
  - `project-status.ts` 의 allDone 판정과 같은 방식이다. **부모 status === 'done' 을 판정에
    쓰지 않는 이유 둘**: (1) round1 반올림 — 리프 99.8 + 완료 형제 4개면 롤업이 100.0 으로
    반올림돼 status done 이 된다, (2) 가중치 0 미완 자식은 가중평균에서 소거돼 롤업 100 이
    가능하다. 두 경우 모두 미완 리프가 실재하므로 리프 원시값 검사만이 안전하다.
- **숨김 대상**: 자식을 가진 노드 N 중 subtreeAllDone(N) 인 것(최대 노드 기준)과 그 하위 전체.
- **흐림 대상**: 화면에 남은 행 중 subtreeAllDone(n) 인 행. 평상시(비검색)에는 숨김 뒤 남는
  subtreeAllDone 행이 리프뿐이므로 "미완 형제 때문에 남은 완료 리프"와 동치이고, 검색·focus
  임시 노출로 전부완료 구간의 부모 행이 화면에 드러나면 그 부모도 같은 규칙으로 흐려진다.
- **최상위 완료 리프**(자식 없는 phase 행)는 '구간'이 아니므로 숨기지 않고 흐림만 한다.
  따라서 프로젝트 전체가 완료면 **최상위 리프를 제외한** 모든 구간이 숨고, 최상위가 전부
  구간(자식 보유)인 트리에서만 빈 상태가 성립한다(아래 UI 절).

## 데이터 흐름과 구현 지점

신규 페치·마이그레이션 없음.

1. **순수 함수 모듈** (신규, `src/lib/domain/hideDone.ts` + `tests/domain/` — 이정표 기준선
   순수 함수 분리 관례 527e086 이 둔 위치와 동일한 도메인 계층):
   `ComputedItem[]` 트리를 받아 숨김 대상 id 집합(과 그 크기 N)을 산출한다.
2. **`WbsGanttSheet.tsx` flatRows** (`389-393`): 유일한 필터 삽입 지점.
   - 검색 중(matchKeep 존재): 기존 그대로 — 숨김 미적용.
   - 검색 아님 + 토글 켜짐: `flatten(items, effCollapsed)` 결과에서 숨김 id 를 제외.
   - 행높이(rowsH)·행번호·지브라·의존선 Y좌표·격자/오늘선/이정표 높이가 전부 flatRows
     파생이므로 시트·간트가 자동 정합된다.
   - `allFlatItems`(394, 의존일정·itemById·상세패널용 전체 트리)와 `rootWeightTotalPct`·
     `milestoneTimeline`·`dependencySchedule` 은 items 전체 기준 그대로 둔다.
3. **`?focus=` 딥링크**: 대상이 숨겨진 구간 안이면 **조상 경로 + 대상 행 + (대상이 자식을
   가지면) effCollapsed 를 적용한 대상 서브트리**를 임시 노출한다 — 대상이 구간 헤더일 때
   하위를 펼칠 어포던스가 없는 화면(접기 토글은 splitParentIds 에만 있음)을 피하기 위함.
   임시 노출 행은 흐림 규칙을 그대로 받는다. 수명은 forcedOpen 과 동일 계열: focus 진입 시
   1회 설정하고, 사용자가 숨김 토글을 조작하거나 toggleAll 을 누르면 걷어낸다.
   토글 저장값은 건드리지 않는다. 구현 힌트: 기존 focus 효과(`WbsGanttSheet.tsx:263-280`)에서
   flashId 와 같은 배치로 set 하면 스크롤 효과는 다음 렌더 후 DOM 을 찾으므로 순서 문제가 없다.
4. **페이지 배선** (`wbs/page.tsx`): `getUiPrefs()` 를 기존 `Promise.all` 에 병렬 추가
   (직렬 await 금지 관례)해 initial prop 으로 주입.
5. **저장**: 토글 클릭 시 `queueUiPref({ wbsHideDone })` 600ms 디바운스.
   사용자 액션에서만 저장이 돌므로 skip-first 참조비교 가드는 불필요.
   `UiPrefs` 인터페이스(`types.ts:177`)에 `wbsHideDone?: boolean` 추가.
   `computePrefsSync` 의 KEYS 에는 넣지 않는다(페이지 initial prop 경로 — minuteFontSize 선례).

## UI

- **토글 버튼**: WBS 툴바에 "완료 숨김" — 이정표 토글과 같은 `aria-pressed` + `btn h-9 px-3
  text-xs` + 활성 시 brand 색 패턴. 시트·간트 양쪽 모드에서 보이는 위치에 둔다.
- **숨은 행 수 병기**: 활성 시 버튼에 "완료 숨김 · N" 형태로 표기. **N = 숨김 id 집합의
  크기(구간 헤더 행 포함, 접힘 상태 무관 — 순수 함수 산출값 그대로)**. 접힘 조작으로 N 이
  흔들리지 않는 것이 의도다: N 은 "화면에서 몇 줄 줄었나"가 아니라 "숨김 기능이 감춘 작업
  수"를 알리는 신호다. **검색 중에는 숨김이 일시 미적용이므로 N 병기를 생략**하고(거짓 신호
  방지) aria-pressed 활성 상태만 유지한다. 별도 배지는 두지 않는다.
- **흐림**: 행 전체 opacity 처리(시트 행 + 간트 막대 동일). display 계열 유틸을 쓰지 않으므로
  반응형 안전망(unlayered 규칙)과 충돌하지 않는다.
- **빈 상태 3번째 분기** (`WbsGanttSheet.tsx:1344-1363`): 기존 분기는 '항목 없음'과
  '검색 결과 없음' 둘뿐. `items.length > 0 && flatRows.length === 0 && 숨김 켜짐 && 검색 아님`
  이면 "모든 작업이 완료되어 숨겨졌습니다" + '숨기기 해제' 버튼을 보여준다.
- **i18n**: 기존 `wbs.*` 사전에 한/영 키 추가.

## 영향 없음 (무접촉 확인 목록)

엑셀 내보내기(`/api/export`)·칸반(수정 금지 범위)·대시보드·주간보고·리스크 신호·봇 도구·
알림·스냅샷/트렌드는 서버에서 `getComputedWbs` 전량 데이터를 독자 조회하므로 영향 없음.
숨김 상태가 데이터 계층으로 새어나가지 않는 것이 이 설계의 불변 조건이다.

## 알려진 트레이드오프 (승인됨)

- 숨겨진 완료 구간이 끝점인 의존 화살표는 함께 사라진다(기존 rowIndex 미스 시 생략 동작,
  `WbsGanttSheet.tsx:1583-1585` — 접기와 동일). 간트 적용 결정 시 안내·수용됨.
- 행번호는 보이는 행 기준으로 재부여된다(접기와 동일).
- `saveUiPrefs` 는 읽기-병합-쓰기라 동시 세션에서 마지막 쓰기가 이긴다 — 기존 계약 그대로.

## 에러 처리

- `getUiPrefs` 조회 실패 시 해당 액션의 기존 계약을 따른다(조회 실패를 데이터 없음으로
  위장하지 않는 3원칙 준수는 기존 구현 책임 범위). 화면은 기본값 '꺼짐'으로 렌더한다.
- 저장 실패는 `debouncedSave` 기존 정책(로컬이 진실, 실패 무시)을 따른다.

## 테스트

- **vitest 단위 테스트** (신규 순수 함수 모듈 대상, `tests/domain/`):
  1. 부분완료 부모(4/5 완료) — 부모·완료 자식 모두 잔존, 완료 자식은 흐림 대상
  2. 전부 완료된 최상위 구간 — 서브트리 통째 숨김
  3. 중간 깊이의 전부 완료 구간(부분완료 phase 아래) — 그 서브트리만 숨김
  4. 가중치 0 미완 자식 엣지 — 부모 롤업 100이어도 숨기지 않음
  5. round1 반올림 엣지 — 리프 원시 99.8 + 완료 형제 4개(부모 status done)여도 숨기지 않음
  6. 원시값 계약 — actualPct 99.5 리프는 완료 아님(숨김·흐림 모두 제외), null 리프는 미완
  7. 최상위 완료 리프 — 흐림만, 숨김 아님
  8. 전량 완료(최상위 리프 없는 픽스처) — 전 행 숨김(빈 상태 분기 조건 성립)
  9. 전량 완료 + 최상위 완료 리프 존재 — 리프는 흐림으로 잔존(빈 상태 아님)
- 검색 우선·focus 임시 노출은 컴포넌트 합성 계약으로 계획 단계에서 테스트 방법 확정.
- display 유틸 미사용이므로 `tests/css/breakpoint-safety-net.test.ts` 영향 없음.

## 범위 제외

- 엑셀 내보내기에 숨김 반영 — 하지 않음(전량 출력 유지).
- 프로젝트별 저장(user_wbs_state 확장) — 전역 저장으로 충분, 마이그레이션 회피.
- 완료 행 접기 애니메이션·전환 효과 — 이번 범위 아님.

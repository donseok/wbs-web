# 회의록 프로젝트 재편(B안) + 나의 회의 프로젝트 구분 — 설계

- 날짜: 2026-08-12
- 상태: 사용자 승인(브레인스토밍 완료), 구현 전
- 범위: 회의록 보관함(`/minutes`) 트리를 프로젝트 축으로 재편(폴더 실소속화), 나의 회의(`/meetings`)에 프로젝트 필터·색상 추가

## 0. 배경과 문제

- 회의록 보관함은 전역 하나이며 트리 최상위가 팀 폴더 5축(0043)이다. 모든 프로젝트의 회의록이 한 트리에 뭉쳐 있다.
- 나의 회의 달력도 전 프로젝트의 내 회의가 한 달력에 섞여 나온다.
- 실측(프로덕션, 2026-08-12): 회의록 65건 중 59건이 `project_id` 보유(0045 백필), 미지정 6건. 프로젝트 2개. `teams`에 프로젝트 소속 행은 0건(0071은 지원만, 전사 5축 PMO/ERP/MES/가공/MDM만 존재).

## 1. 사용자 결정 사항 (브레인스토밍 Q&A)

| 질문 | 결정 |
|---|---|
| 분리 형태 | 전역 보관함을 **프로젝트 축으로 재편** (프로젝트 메뉴 신설 아님) |
| 프로젝트 하위 구조 | **팀 폴더 유지** — 프로젝트 → 팀 폴더 → 하위 폴더 → 회의록. 미지정 그룹 별도 |
| 나의 회의 | **필터 칩 + 프로젝트 색상** (달력 하나 유지) |
| 구현 접근 | **B안: 폴더 자체를 프로젝트 소속으로 재편**(스키마 변경). A안(코드 합성 파생 뷰) 기각 |
| 폴더 루트 시드 기준 | **프로젝트 팀 마스터**(0071 유효 팀: 프로젝트 팀 있으면 그것, 없으면 전사 폴백 — `teamsForProjectSync` 규칙 그대로) |

설계자 기본값(사용자 확인 완료):
- 회의록의 프로젝트 변경 시 같은 폴더 경로를 새 프로젝트 트리에 **자동 재편철**.
- 나의 회의 필터 상태는 저장하지 않음(URL/로컬 상태만).

## 2. 데이터 모델 — 마이그레이션 0072

### 2.1 스키마

```sql
alter table minute_folders add column project_id uuid
  references projects(id) on delete cascade;  -- null = 미지정 영역
```

- 루트 이름 유니크 재편(부분 인덱스 2개로 분리):
  - `(name) where parent_id is null and project_id is null` (기존 인덱스 교체)
  - `(project_id, name) where parent_id is null and project_id is not null`
- 하위 폴더 유니크 `(parent_id, name)`은 그대로 — 부모가 프로젝트를 함의한다.
- 조회 인덱스: `minute_folders (project_id)`.
- **불변식: 자식 폴더의 `project_id`는 부모와 같다.** 폴더 생성·이동 경로가 코드에서 보장하고, 백필 스크립트 VERIFY가 검사한다.

### 2.2 시드

- 회의록이 있는 각 프로젝트에 유효 팀 마스터의 **활성 팀코드**로 루트 폴더 생성. `created_by null` = 시드 표식(0043 관례 유지 — 스쿼팅 방어·보호 판정에 사용).
- 현행 전사 트리는 **이동 없이 그대로 미지정 영역**(project_id null)이 된다.

### 2.3 백필 — Node 스크립트 (SQL 아님)

- 전례: `scripts/apply-0043.mjs`. SQL로 재귀 경로 복제를 재구현하면 라이브 편철 로직(`resolveFolderPath`)과 어긋나는 두 번째 구현이 생긴다.
- 절차: `project_id`가 있는 회의록의 현재 폴더 경로를 읽어 → 소속 프로젝트 트리에 동일 경로 확보(`resolveFolderPath` 재사용, 없으면 생성) → `folder_id` 재지정.
- dry-run 모드 → 검증 출력 → 실행. VERIFY: 재편 후 "프로젝트 있는 회의록의 폴더는 같은 프로젝트 소속" 위반 0건, 미지정 회의록 폴더 무변경.
- 백필 스크립트는 실행 전 각 회의록의 `(id, 기존 folder_id)` 스냅샷을 `outputs/`에 남긴다 — 롤백 시 편철 위치 복원용.
- 롤백: `0072_*_rollback.sql` — **컬럼·인덱스 원복 + 프로젝트 소속 폴더 행 삭제**(`on delete set null`로 회의록은 미분류 강등, 본문 데이터 소실 없음). 편철 위치는 위 스냅샷으로 스크립트 복원한다.
- G4 대상(0072+): 스테이징 리허설 + `Staging-verified:` 트레일러 필수.

## 3. 편철 규칙 — `src/lib/minutes/folders.ts`

- 스냅샷·경로 해석에 `projectId: string | null` 차원 추가. `seedRoots`는 `(projectId, 팀코드)` 키.
- `resolveTeamRootFolderId`, `resolveFolderPath`, `normalizeFolderPath`의 팀코드 검증은 **그 프로젝트의 유효 팀 마스터**(`activeTeamCodesForProjectSync`, 미지정은 전사 활성 코드) 기준으로 바꾼다.
- **지연 보장(lazy ensure)**: 편철 시점에 프로젝트 트리에 팀 루트가 없고 팀코드가 유효 마스터에 있으면 시드로 자동 생성. 프로젝트 생성 경로에는 손대지 않는다.
- 또박또박 외부 API(v1/minutes, v1/minutes/folder): **계약 무변경**. 프로젝트 판정은 현행(연결 회의의 project_id)이며, 확정 시 그 프로젝트 트리·미확정 시 미지정 트리를 기준으로 folder_path를 해석한다.
- 프로젝트 변경(메타 수정 `updateMinuteMeta`, 배치 `assignMinutesProject`, 회의 연결 변경): 기존 폴더 경로를 새 프로젝트 트리에 자동 재편철(없으면 생성). 실패 시 미분류 폴백 — "편철이 등록을 막지 않는다" 철학 유지, 실패는 로깅.
- 팀 마스터 변경(팀 추가·개명·비활성)에 폴더는 소급 반응하지 않는다. 다음 편철 때 새 루트가 생기고, 옛 루트는 회의록과 함께 남아 수동 정리한다.

## 4. 화면 — 회의록 보관함 `/minutes`

- 트리 최상위 = **프로젝트 노드**(내 프로젝트 우선 정렬 `sortMyProjectsFirst` 관례) + **미지정** 노드. 그 아래는 기존 폴더 트리 UI(MinutesExplorer) 재사용.
- 비공개 프로젝트는 기존 `dropHidden`/`getHiddenProjectIds` 규칙으로 노드째 숨김(그 프로젝트 회의록은 이미 걸러진다).
- 폴더 CRUD 모달(FolderManageModal·FolderPickModal)에 프로젝트 컨텍스트 전달. 시드 루트 보호(개명·삭제 불가) 유지. 폴더 이동은 **같은 프로젝트 안에서만** — 프로젝트 간 이동은 회의록 단위(메타 수정)로만 한다.
- 챗 폴더 칩(0066)은 folder_id 기반이라 동작 유지. 폴더 픽커에 프로젝트 그룹 라벨만 추가.
- 달력 뷰·즐겨찾기·뷰어·히어로 KPI 무변경.
- 미지정 회의록에 프로젝트를 붙이는 수단은 기존 메타 모달로 충분(신규 UI 없음).

## 5. 화면 — 나의 회의 `/meetings`

- 스키마 무변경(meetings.project_id는 not null).
- 달력 상단 **프로젝트 필터 칩**(전체 + 프로젝트별) + 회차 pill **프로젝트별 색상**(프로젝트 목록 순서 기반 결정적 팔레트, 기존 토큰 시스템 준수 — dkflow-design-consistency).
- 필터 상태는 저장하지 않는다(로컬 상태만). 프로젝트별 회의 달력 `/p/[id]/meetings`는 무변경.

## 6. 권한·에러 처리

- 프로젝트 폴더의 생성·개명·이동·삭제 서버 액션에 `requireProjectMember(projectId)` 가드 추가. 미지정 영역 폴더는 현행 규칙(생성=본인, 수정·삭제=생성자 or 관리자 관례) 유지.
- 폴더 RLS는 현행 유지 — 서버 액션 가드가 1차 관문(회의록 계열은 service_role 쓰기라 RLS 2차 방어선이 없다는 기존 주의 그대로).
- 조회 실패는 null 반환+로깅(빈 트리 위장 금지). 쓰기 전 선행 조회 실패 시 중단. fail-closed.

## 7. 테스트·검증

- 단위: 프로젝트 스코프 스냅샷/경로 해석(기존 folders 테스트 확장), 프로젝트 변경 재편철, 미지정 폴백, lazy ensure 경합(23505 재조회 경로).
- 마이그레이션 테스트(`tests/migrations/` 전례): 인덱스 재편·시드 멱등·자식 project_id 불변식.
- 스테이징 리허설(G4): `staging:sync` → `db:apply --target staging` → 백필 dry-run → 실행 → 스테이징 화면 확인 → `Staging-verified:` → staging push → `db:apply --target prod` → main push.
- 실화면: 트리 프로젝트 분리·미지정 6건 표시·또박또박 스모크(스테이징)·나의 회의 칩과 색상·비공개 프로젝트 숨김.

## 8. 범위 밖 (하지 않는 것)

- 프로젝트 메뉴(`/p/[id]/minutes`) 신설 — 사용자가 전역 재편을 선택.
- 또박또박 API 계약 변경(team↔프로젝트팀 매핑 신설 등).
- 위키 관련 일체(서비스 중단, 작업 금지 지시).
- 프로젝트 팀 마스터 데이터 생성(0071 데이터 채우기) — 폴백 규칙이 흡수.
- 나의 회의 필터 상태 계정 동기화.

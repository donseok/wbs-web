# 자율 러너 설계 검토 보고 (2026-08-21)

대상: `2026-08-20-wbs-autonomous-runner-design.md` (승인된 정본) · 검토 방식: 적대 검토
에이전트 1 + 독립 비교 1 + 코드·계약 실물 대조(depends.ts·dflow.sh·agentTokens.ts·api-contract.md).
**설계 골격(단발 실행형·결정적 게이트·자율화 사다리)은 검토를 버텼다.** 아래는 착수 전 개정이
필요한 발견들이다 — 정본 수정 권한은 설계 소유자에게 있으므로 이 문서는 제안만 한다.

## 치명 — 무인 루프의 기본 경로가 깨진다

**① evidence 는 approved 전용인데 루프는 승인 비동기다.**
depends_evidence 는 approved 주문의 completion 보고에서만 추출된다(`src/lib/agent/depends.ts:34-38`).
설계 §3 은 "승인은 비동기로 밀려도 루프는 계속"을 핵심으로 선언 — 그러면 야간에 선행이
reported(미승인)인 동안 후행의 evidence 는 빈 배열이고, dflow.sh 의 조상 검사는 head_sha null 을
건너뛰어 **조용히 통과**한다. §4-2 가 고치려는 "하드 실패"가 아예 안 나고, 선행 코드 없는 main
위에서 후행이 구현된다(스태킹 경로는 진입 자체가 불가). §4-2 는 시끄러운 실패만 고치고 조용한
통과를 놓쳤다 — 이게 무인 운영의 기본 경로다.
→ 제안: evidence 를 reported 시점에 노출하도록 계약 개정, 또는 무인 체인 진행을 승인에 묶는다.

**② 반려가 후행 게이트를 닫지 않는다.**
reject 는 stage 무변경(im 유지, api-contract 전이 표)이고 서버 선행 게이트는 stage≥im 만 본다
(`claim/route.ts:62`). 아침에 T1 을 반려해도 T2·T3 claim 은 계속 열려 있어 **기각된 코드 위에서
체인이 계속 자란다.** "PR 머지는 사람" 안전장치는 머지만 막지 체인 진행은 못 막는다.
→ 제안: 반려 시 stage 역전이(또는 후행 claim 차단 플래그) 추가.

**③ 게이트에 하한이 없다.**
빌드·테스트·린트·diff **상한**뿐이라, 기준선 초록 리포에서 빈 diff·테스트 삭제·no-op 이 전부
통과해 PR·done·후행 개방까지 간다. 파일럿 성적도 오염된다(no-op 완주가 '성공' 집계).
→ 제안: 하한 게이트 3건 — 빈 diff 거부 · 테스트 파일 삭제/수정 감지 · **diff 에 새 테스트 포함
요구**(과정 규율 정본 `docs/agent/claude-skill/dev-discipline.md` 의 TDD 규율과 쌍).

## 중대 — Phase 0 에 승격할 것

- **④ 워커 실행 표면 미결정**: `claude -p` + acceptEdits 는 Bash 가 없어 워커가 테스트를 못 돌린다
  — 눈감고 코드 작성 → 게이트 실패 → 재시도로 구독 소진. Bash allowlist 를 열면 §9 위협 모델을
  다시 써야 한다(읽기 제한 없는 무인 push 는 유출 게이트가 push 뒤에 있음). 사실상 Phase 0 4번째 블로커.
- **⑤ 침묵 실패의 러너-외부 검출 부재**: 아침 리포트·work.stalled 전부 러너/조회에 의존 — launchd 가
  멈추면 신호 부재가 유일한 신호(B안 기각 사유의 재현). 절전과 StartInterval 의 모순(실행 사이
  간격에 잠들면 다음 기동 없음)도 미해결 — 전원·절전 정책은 L1 하드 전제인데 구체 결정이 없다.
- **⑥ Phase 1 에스컬레이션 채널 부재**: 에이전트 API 에 알림 발행 엔드포인트가 없고 §5 는 "Phase 1
  서버 변경은 발급 1건뿐" — §7 의 "예외만 사람 호출"은 Phase 1 에서 성립하지 않는다.
- **⑦ 스태킹의 squash 비호환**: 선행이 squash 머지되면 후행 브랜치의 선행 커밋이 main 과 중복 →
  후행 PR 충돌 확정. §12 ② "스태킹이 흡수" 서술과 달리 머지 정책은 §4-2 의 전제다. 검사 시점
  문제도 있음 — 조상 검사는 claim 전·현재 HEAD 기준(dflow.sh)인데 워크트리·스태킹은 claim 후다.

## 관계 정리 (경쟁 아님)

같은 날 작성된 대화형 스킬 `dflow-dev`(.claude/skills/dflow-dev/)는 이 설계의 **L0(supervised)
경로**로 정렬했다 — 무인 영역 침범 없음, §2 기각·재제안 금지 존중. 구현 과정 규율은
`docs/agent/claude-skill/dev-discipline.md` 로 추출해 러너 킥오프 프롬프트와 스킬이 같은 정본을
참조하게 했다(규율 drift 차단). 러너 착수 시 이 문서와 하한 게이트(위 ③)만 연결하면 된다.

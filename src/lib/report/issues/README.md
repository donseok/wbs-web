# 이슈 분석서 보고서 계약

이 디렉터리는 이슈관리 데이터를 PPT 템플릿의 다음 두 종류 페이지에 공급하는 직렬화
가능한 보고서 모델을 정의한다.

- 영역별 이슈 종합
- 이슈별 개선기회 도출

프로세스 체계와 원인 분석 페이지는 자동 작성 범위에서 제외한다. 기본 분석 대상은 상태와
관계없이 사전 점검을 통과한 프로젝트의 모든 이슈다.

최종 슬라이드 조립 규칙은 다음과 같다.

- 표지와 목차(원본 1~4)는 유지한다.
- 프로세스 체계/정의(원본 5~7)는 제외한다.
- 영역별 이슈 종합(원본 8~9)은 Mega별 데이터 양에 맞춰 동적으로 반복한다.
- 근본원인(원본 10)은 현재 범위에서 제외한다.
- 개선기회 목차(원본 11)는 유지한다.
- 개선기회 상세(원본 12)는 주요 이슈와 개선기회 블록을 페이지 높이 안에서 함께
  배치하고, 내용이 넘칠 때만 2·3페이지 이상으로 동적으로 반복한다. 한 개선기회에
  연결할 이슈는 최대 5개다.

## 템플릿 계약

런타임 템플릿의 고정 경로는
`src/lib/report/assets/issue-analysis-template.pptx`다. 파일은 ZIP 매직 바이트(`PK`)로
시작하는 보호 해제된 OOXML PPTX여야 한다.

보안 승인된 표준 OOXML 작업 사본을 런타임 자산 경로에 등록했다. `template.ts`는 파일이
없으면 `missing`, DRM 래퍼이거나 OOXML이 아니면 `protected`, 정상 ZIP 헤더면 `ready`로
명시한다. 원본 슬라이드 디자인을 추정해 새로 만들지 않고 등록된 작업 사본을 정본으로
사용한다.

## 렌더러 경계

분석 데이터 생성, 덱 페이지 계획, PPT 렌더링을 분리한다. `deckPlan.ts`는 템플릿의
고정/반복 페이지와 데이터 배치를 결정하며 렌더링 엔진이나 파일 IO에 의존하지 않는다.
보고서 모델과 AI 실행 결과는 템플릿 유무와 무관하게 생성·감사할 수 있지만, 다운로드
렌더러는 템플릿 진단이 `ready`일 때만 동작해야 한다.

- 8페이지 형식: Mega별 첫 페이지(표 기본 행 높이 예산 3)
- 9페이지 형식: 후속 페이지(표 기본 행 높이 예산 5) 반복
- 12페이지 형식: Mega 순서와 기회 순서를 유지한 채 여러 개선기회 블록을 페이지
  높이 예산 안에 연속 배치한다. Mega 경계만으로 페이지를 나누지 않으며 각 블록에
  `02-영업`과 같은 영역을 표시한다.
- 표시 ID/내용 연결: 템플릿 샘플이 아니라 DB UUID → PI ID 매핑을 정본으로 사용
- 제목·본문·Sub Process·원천은 인위적으로 줄이거나 `…`/`외 N개`로 바꾸지 않는다.
- 등록 본문의 개행과 `[현황]`·`[문제/영향]`·`[필요 조치]` 구조를 보존한다.
- 열 너비별 예상 줄 수로 행 높이와 페이지당 행 수를 조정하고, 한 페이지보다 긴
  이슈는 동일 PI ID의 `계속 N/M` 행으로 손실 없이 이어서 표시한다.
- 동적 표 행에는 원본 11pt 서식과 자동 맞춤을 함께 적용해 렌더러별 줄바꿈 차이를
  흡수한다.
- 개선기회 제목·설명과 연결 이슈 제목도 예상 줄 수로 높이를 계산한다. 한 블록이
  페이지보다 길면 `계속 N/M` 블록으로 나누며 모든 조각을 합쳤을 때 원문이 그대로
  복원되어야 한다.

`storedRun.ts`는 다운로드 시 `issue_analysis_runs.analysis_json`을 현재 v1 스키마,
프로젝트, Mega 순서, PI ID, 영역 요약, 개선기회 UUID 연결까지 다시 검증한다. 브라우저가
보낸 분석 본문은 PPT 입력으로 사용하지 않는다.

`/api/issue-analysis`는 이 저장 실행을 덱 계획으로 바꾸는 다운로드 경계다.
운영 렌더러는 사용자가 승인한 JSZip 방식으로 표준 PPTX 패키지를 복제·치환한다.
`jszipRenderer.ts`는 각 출력 페이지를 `deckPlan.ts`의 `sourceSlide`에서 복제한 뒤,
명시된 shape ID·표 셀·연결선만 수정한다. 테마·마스터·레이아웃·원본 서식은 그대로
보존하고, 출력 슬라이드 관계·콘텐츠 타입·문서 메타데이터만 새 페이지 순서에 맞춰
재배선한다.
